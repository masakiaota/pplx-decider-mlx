# pplx-decider-v1.3-mlx

MLX weights of [perplexity-ai/pplx-decider-v1.3](https://huggingface.co/perplexity-ai/pplx-decider-v1.3) (27B) for
Apple silicon Macs, for use with [decider-mlx](https://github.com/masakiaota/pplx-decider-mlx).

**This is an unofficial derivative. It is not affiliated with, endorsed by or supported by Perplexity AI.** The
original model, its training and its evaluation are Perplexity's work; see the original model card. Problems with
this conversion belong in the decider-mlx issue tracker, not with Perplexity.

The weights only run with decider-mlx: most linear layers use a custom row-wise 4-bit layout and a W4A8 matrix
product, and a generic MLX loader will not reproduce the model. decider-mlx does not run the official BF16 weights
either.

## Usage

Requirements: a Mac with an M5 chip or later, 36 GB of memory or more recommended, macOS 27 or later, Python 3.14 and [uv](https://docs.astral.sh/uv/).

```sh
git clone https://github.com/masakiaota/pplx-decider-mlx && cd pplx-decider-mlx
uv sync
uv run decider-mlx fetch --model pplx-decider-v1.3      # this repository, at a pinned revision
uv run decider-mlx serve --model pplx-decider-v1.3 --port 8001
```

```sh
curl -s localhost:8001/v1/decisions -H 'Content-Type: application/json' -d '{
  "model": "pplx-decider-v1.3",
  "state": "My integration keeps failing with a 401 since we rotated our API key.",
  "questions": {"urgent": {"type": "noul", "instructions": "Is the customer blocked right now?"}}}'
```

The server takes the official Decisions API body (`POST /v1/decisions`). From Python:

```python
from decider_mlx import load
app = load("pplx-decider-v1.3")
app.decide({"state": "...", "questions": {"q": {"type": "noul", "instructions": "..."}}})
```

`serve`, `run` and `load()` download this repository automatically when it is not in the Hugging Face cache, and
`decider-mlx fetch` checks every file against `manifest.json` (sha256). See the decider-mlx README for batching,
isolated mode, temperature, Locate and image inputs.

## Conversion

| Part | Format |
|---|---|
| Language-model linear layers except k/v projections (`rowq4/`, 368 files) | row-wise symmetric 4-bit: one scale per output row (absmax/7 after a per-row scale search), codes stored as signed int4 ("s4"). Rounding uses GPTQ-style error compensation with act-order, calibrated on about 240K tokens from BoolQ, SQuAD v2 and Qasper training splits and SQuAD Locate requests, with no overlap with the evaluation sets. decider-mlx multiplies them with INT8 activations (W4A8). |
| k/v projections of the 16 full-attention layers (`model-rest.safetensors`) | group-64 affine 4-bit in MLX's format (see `mlx_config.json`) |
| Embedding, normalization, convolution, DeltaNet gate projections (`in_proj_a`, `in_proj_b`), vision tower, readout head | unchanged from the original (BF16), in `model-rest.safetensors` and `readout.safetensors` |
| Locate (`locate/`) | the original rank-64 Locate LoRA in BF16 (`adapter.safetensors`, applied at run time on top of the 4-bit weights) and the original span head. Loaded only on the first Locate request. |
| Tokenizer, processor, `config.json`, `decision_config.json`, `joint_config.json`, chat template | unchanged copies of the original repository |

Mapped weights: 16.67 GB including Locate. The original BF16 language model is 51.25 GB.

The scripts that build these files from the original checkpoint are in [tools/convert](https://github.com/masakiaota/pplx-decider-mlx/tree/main/tools/convert) of decider-mlx.

## Agreement with the original model

Measured against BF16 reference outputs of the original model (an MLX port that matches the official PyTorch
implementation: 100/100 decisions on the gate set, mean |dp| 0.0014), on held-out evaluation sets:

| Question type | Same answer as BF16 |
|---|---|
| Binary (`noul`) | 717/726 |
| `choice` | 161/164 |
| `score` (argmax) | 70/74 |
| Locate span sets | 100/114 |
| BoolQ gate, 4 execution conditions | 100/100 each |

Probabilities differ more than for 8-bit weights (mean |dp| against BF16 0.019 on binary questions). Locate span
agreement on a larger set is 267/300 (an earlier group-64 4-bit build: 280/300), while agreement with gold labels is
at the original model's level (F1 0.697 vs 0.685). Method and per-technique results:
[experiments/](https://github.com/masakiaota/pplx-decider-mlx/tree/main/experiments).

## Speed and memory (Mac Studio, M5 Ultra, decider-mlx 0.1)

| Case | Time |
|---|---:|
| Process start to accepting HTTP requests | 0.3-0.5 s |
| Process start to the first answer (427 tokens) | 0.6-1.0 s |
| Single request, 427 tokens (repeated) | 220 ms |
| 20 requests in one array | 1.92 s |
| 520 mixed requests, one at a time over HTTP | 117 s (median 135 ms) |
| Long input: 5.4K / 12.9K / 32.4K tokens | 2.66 / 7.62 / 22.9 s |
| 1,072 mixed requests in arrays (bulk packing) | 236 s |

Startup preparation (compiling the graphs for common shapes) runs in the background between requests and is done
after about 7.4 s; answers do not depend on it.

Memory: 16.67 GB of memory-mapped weights including Locate. MLX peak 23.7 GB after the HTTP benchmark and 25.0 GB
for a 32K-token Locate request (the original BF16 model peaks at 57.1 GB); about 1.7 GB RSS, because the weights
are memory-mapped.

## Files

`manifest.json` lists the size and sha256 of every file except this README. `mlx_config.json` describes the
quantization (group-64 modules in `model-rest.safetensors`, row-wise modules in `rowq4/`). `LICENSE` is the original Apache-2.0 license, and `NOTICE` keeps the
original notice and lists the modifications.
